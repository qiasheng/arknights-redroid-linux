# 01 · 环境与容器

## 0. 前置检查

先确认宿主具备跑 redroid 的条件。缺一项都可能在 `podman logs` 里看到奇怪的错误。

```bash
# 内核
uname -r

# binder：新内核是 binderfs，旧内核是 /dev/binder
ls -l /dev/binder* /dev/binderfs 2>&1

# 内核配置（有 /proc/config.gz 才行）
zgrep -E 'CONFIG_ANDROID_BINDER|CONFIG_ASHMEM' /proc/config.gz

# GPU（走 host 渲染才需要）
ls -l /dev/dri/

# 工具
podman --version
adb version
```

本机的情况（供对照）：

```
内核 7.2.x-zen
CONFIG_ANDROID_BINDER_IPC is not set
CONFIG_ANDROID_BINDER_IPC_RUST=y
CONFIG_ANDROID_BINDER_DEVICES=""
/dev/binder -> /dev/binderfs/binder
没有 /dev/ashmem
```

要点：

- **binder**：必须有。`BINDER_DEVICES` 为空时用 binderfs，redroid 镜像会自己挂；容器必须 `--privileged`。
- **ashmem**：新内核已经移除，靠 `androidboot.use_memfd=1` 用 memfd 替代。不加这个参数，部分 Android 版本会在启动时卡住/报错。
- **GPU**：`/dev/dri` 存在才能用 `redroid_gpu_mode=host`；没有核显/独显也能跑，但只能软件渲染，游戏会很卡。
- **podman**：本方案用 **rootful**（命令前 `sudo`）。rootless 下 `--privileged` 和网络配置限制更多，不推荐。
- **adb**：Arch 上是 `android-tools` 包：

  ```bash
  sudo pacman -S android-tools
  ```

  ⚠️ 不要为了抓包顺手装 `tcpdump`，在 Arch 上它可能触发 `libcrypto.so=3-64` 依赖冲突，把 podman/git/curl 一起搞坏（见 07 第 11 节）。

- **磁盘**：游戏本体 + 资源大约 10–20 GB，`~/redroid-arknights` 至少留 30 GB。

## 1. 拉镜像

```bash
podman pull docker.io/redroid/redroid:11.0.0-latest
```

Android 11（SDK 30）是当时的稳定选择。Android 13 镜像也可以，但翻译层与 guest 库的版本匹配关系不同，本记录只覆盖 11。

## 2. 创建容器

```bash
mkdir -p ~/redroid-arknights

sudo podman run -itd \
  --privileged \
  --device /dev/dri:/dev/dri \
  -v ~/redroid-arknights:/data:rprivate,rbind \
  -p 127.0.0.1:5556:5555 \
  --name redroid-arknights \
  docker.io/redroid/redroid:11.0.0-latest \
  androidboot.use_memfd=1 \
  androidboot.redroid_width=1280 \
  androidboot.redroid_height=720 \
  androidboot.redroid_dpi=240 \
  androidboot.redroid_gpu_mode=host \
  androidboot.redroid_fps=60
```

要点：

- `--privileged`：redroid 需要挂 binder、改网络等，必须给。
- `--device /dev/dri:/dev/dri` + `redroid_gpu_mode=host`：走宿主 GPU，AMD / Intel 都能用。没有 `/dev/dri` 就删掉这两处，改用软件渲染（能跑但卡）。
- `redroid_width/height/dpi` 是**物理**分辨率。之后可以用 `wm size` / `wm density` 覆盖（见第 5 节）。
- `androidboot.redroid_fps=60`：显示刷新率。不写默认 30（详见 2.1）。
- 端口用 5556，避免与已有的崩铁容器（5555）冲突。**建议绑回环** `-p 127.0.0.1:5556:5555`；写成 `-p 5556:5555` 会监听 `0.0.0.0`，同局域网可连（ADB 无认证）。
- `/data` 落在宿主，`podman rm` 重建后数据还在；`/system` 的修改则不在 `/data` 里（见第 8 节）。

创建后核对参数：

```bash
sudo podman inspect redroid-arknights --format '{{json .Config.Cmd}}'
sudo podman inspect redroid-arknights --format '{{json .HostConfig.Binds}} {{.HostConfig.Privileged}}'
```

本机实际值：

```
["androidboot.use_memfd=1","androidboot.redroid_width=1280","androidboot.redroid_height=720",
 "androidboot.redroid_dpi=240","androidboot.redroid_gpu_mode=host","androidboot.redroid_fps=60"]
["/home/<you>/redroid-arknights:/data:rprivate,rbind"] true
```

> 如果之后改端口/挂载，必须 `podman rm` 重建容器；`podman restart` 不会应用新的 `run` 参数。重建前先确认 `/data` 目录还在。

### 2.1 帧率：默认只有 30，不是 60

redroid 的 `androidboot.redroid_fps` 默认值是 **30**（`gpu_mode=host`；没有 GPU 时是 15）。没传这个参数，容器就是 30Hz：

```bash
adb -s 127.0.0.1:5556 shell getprop ro.boot.redroid_fps
# 30

adb -s 127.0.0.1:5556 shell dumpsys display | grep -m2 'fps='
# fps=30.000002

adb -s 127.0.0.1:5556 shell dumpsys SurfaceFlinger | grep -m1 'refresh-rate'
# refresh-rate : 30.000000 fps
```

实测 `androidboot.redroid_fps=60` 和 `=120` 都能正常起来（临时容器验证过，display 分别报 60.000004 / 120.00001）。但**方舟客户端自身通常以 60 为上限**，填 120 不会让游戏真的跑 120；手动玩或 MAA 自动战斗用 60 就够，纯挂机不需要高帧率时 30 更省资源。

改帧率必须**重建容器**（`Cmd` 不能热改），并且要保住 `/system` 里的翻译层和指纹。先用 `commit` 把当前配置存成镜像：

```bash
sudo podman stop redroid-arknights
sudo podman commit redroid-arknights redroid-arknights:fps60
sudo podman rm redroid-arknights

sudo podman run -itd --privileged --device /dev/dri:/dev/dri \
  -v ~/redroid-arknights:/data:rprivate,rbind \
  -p 127.0.0.1:5556:5555 --name redroid-arknights \
  redroid-arknights:fps60 \
  androidboot.use_memfd=1 \
  androidboot.redroid_width=1280 \
  androidboot.redroid_height=720 \
  androidboot.redroid_dpi=240 \
  androidboot.redroid_gpu_mode=host \
  androidboot.redroid_fps=60
```

> `podman commit` 会把 `/system` 的修改（libndk、禁用 libvulkan、build.prop）一起打包；`/data` 是 bind mount，不会进镜像，游戏和登录态还在。如果不想 commit，就重建后重跑第 6 节和 `docs/02`。

起来后确认：

```bash
adb connect 127.0.0.1:5556
adb -s 127.0.0.1:5556 shell getprop ro.boot.redroid_fps      # 60
adb -s 127.0.0.1:5556 shell dumpsys display | grep -m1 'fps=' # fps=60.000004
```

别忘了新容器还要跑一次 `scripts/start-arknights.sh`（MTU、私有 DNS、常亮都会重置）。

## 3. 首次开机后必做

```bash
adb connect 127.0.0.1:5556

# 等开机完成
while [ "$(adb -s 127.0.0.1:5556 shell getprop sys.boot_completed | tr -d '\r')" != "1" ]; do sleep 3; done
```

然后：

```bash
# 关掉私有 DNS（避免 DoT 到被墙的解析器）
adb -s 127.0.0.1:5556 shell settings put global private_dns_mode off

# 关掉强制门户检测（否则系统可能判定 PARTIAL_CONNECTIVITY）
adb -s 127.0.0.1:5556 shell settings put global captive_portal_mode 0
```

> 这两条和 MTU 一样，**容器重启就丢**，每次都要补。

## 4. 安装 APK

APK 从**官方渠道**下载（官网 / 官方公告里的下载页），不要用来路不明的改包。本记录用的是国服 2.7.x。

**必须按 ABI 安装**：

```bash
adb -s 127.0.0.1:5556 install --abi arm64-v8a arknights-hg-2791.apk
```

原因：APK 里同时带 `lib/x86_64` 和 `lib/arm64-v8a`。直接拖进模拟器窗口 / 不带 `--abi` 时，常常会装成 x86 版本，于是走的是 x86 原生库而不是 ARM 翻译层，行为完全不一样（缺 ARM 库、SDK 初始化异常）。

装完确认一下：

```bash
adb -s 127.0.0.1:5556 shell dumpsys package com.hypergryph.arknights | grep -A2 primaryCpuAbi
# 期望看到 arm64-v8a
```

更新版本时用 `-r` 覆盖安装（保留数据）：

```bash
adb -s 127.0.0.1:5556 install -r --abi arm64-v8a arknights-latest.apk
```

如果报 `INSTALL_FAILED_VERSION_DOWNGRADE`，说明装的是旧包，加 `-d` 或先卸载；如果报签名冲突，说明之前装的是别的渠道包，只能卸载重装（会丢登录态）。

## 5. 分辨率

README 里记录的可用配置是 **1920x1080 / DPI 320**，用 `wm` 覆盖即可（不用重建容器）：

```bash
adb -s 127.0.0.1:5556 shell wm size 1920x1080
adb -s 127.0.0.1:5556 shell wm density 320
```

确认：

```bash
adb -s 127.0.0.1:5556 shell wm size      # Physical size + Override size
adb -s 127.0.0.1:5556 shell wm density
```

> 坐标都是按 1920×1080 记的。如果换分辨率，所有 `input tap` 坐标都要按比例换算。

## 6. ARM 翻译层（关键）

redroid 11 镜像自带的 libndk 是 2021 年的 v0.2.2，太旧，跑不动现在的方舟（IL2CPP + 新版 Unity）。需要换成 ChromeOS Android 13 zork 的 **v0.2.3**。

### 6.1 下载

```bash
curl -L -o /tmp/chromeos_ndk.zip \
  https://github.com/ilhan-athn7/android_proprietary_native_bridge/releases/download/chromeos_zork/chromeos_Android_13_zork_r126.zip
mkdir -p /tmp/ndk && unzip -o /tmp/chromeos_ndk.zip -d /tmp/ndk
```

解压后结构：

```
/tmp/ndk/system/lib64/          # 64 位 host 侧翻译层 + proxy_* 库
/tmp/ndk/system/lib64/arm64/    # 64 位 guest 库（整套，约 59 个 .so）
/tmp/ndk/system/lib/            # 32 位 host 侧
/tmp/ndk/system/lib/arm/        # 32 位 guest 库（整套，约 59 个 .so）
```

> 数量会随 release 略有出入，不要按个数校验；按文件清单整目录覆盖即可。

### 6.2 铺进 /system

redroid 的 `/system` 是**可写**的（不需要 remount，重启后依然有效）：

```bash
adb -s 127.0.0.1:5556 push /tmp/ndk /data/local/tmp/ndk

adb -s 127.0.0.1:5556 shell 'su 0 sh -c "
  cp -a /data/local/tmp/ndk/system/lib64/libndk_translation*.so /system/lib64/
  cp -a /data/local/tmp/ndk/system/lib/libndk_translation*.so   /system/lib/
  cp -a /data/local/tmp/ndk/system/lib64/arm64/*.so             /system/lib64/arm64/
  cp -a /data/local/tmp/ndk/system/lib/arm/*.so                 /system/lib/arm/
  chown 0:0 /system/lib64/libndk_translation*.so /system/lib/libndk_translation*.so \
            /system/lib64/arm64/*.so /system/lib/arm/*.so
  chmod 644 /system/lib64/libndk_translation*.so /system/lib/libndk_translation*.so \
            /system/lib64/arm64/*.so /system/lib/arm/*.so
  sync
"'
```

### 6.3 校验

```bash
adb -s 127.0.0.1:5556 shell 'su 0 md5sum \
  /system/lib64/libndk_translation.so \
  /system/lib64/libndk_translation_exec_region.so \
  /system/lib/libndk_translation.so'
```

期望（这是 v0.2.3 的值）：

```
0f8376da34ee3edd10e79105aec478f4  /system/lib64/libndk_translation.so
088bacc5e921dabbd826b51ef075d09b  /system/lib64/libndk_translation_exec_region.so
51b9189d2bac884b07f2fcd4a11295fe  /system/lib/libndk_translation.so
```

### 6.4 **必须禁用 guest 的 libvulkan.so**

```bash
adb -s 127.0.0.1:5556 shell 'su 0 mv /system/lib64/arm64/libvulkan.so /system/lib64/arm64/libvulkan.so.disabled'
```

不做这一步，游戏启动就会：

```
F ndk_translation: Unable to load library "libvulkan.so"
                   (upon using symbol "android_convertGralloc0To1Usage")
F libc: Fatal signal 6 (SIGABRT) in tid xxxx (pool-2-thread-1)
```

简单说：v0.2.3 给 guest `libvulkan.so` 建 proxy 时，要求**宿主** `libvulkan.so` 导出 `android_convertGralloc0To1Usage`，而那是 Android 13 的符号，Android 11 没有。禁掉 guest 的 libvulkan，Unity 自动回落 GLES，渲染正常（方舟本来就用 GLES）。

禁用后确认：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 ls -l /system/lib64/arm64/libvulkan.so*'
# 只应看到 libvulkan.so.disabled
```

## 7. 重启并确认

```bash
sudo podman restart redroid-arknights
sleep 20
adb connect 127.0.0.1:5556
```

重启后复查（翻译层和 guest 库在 `/system`，是持久的）：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 md5sum /system/lib64/libndk_translation.so'
# 仍是 0f8376da34ee3edd10e79105aec478f4
```

## 8. 持久化：restart 与 rm 的区别

这是最容易踩的坑之一。

| 操作 | `/data`（bind mount） | `/system` 修改（翻译层、build.prop、libvulkan） |
|---|---|---|
| `podman restart` | 保留 | **保留** |
| `podman stop` / `start` | 保留 | **保留** |
| `podman rm` + 重新 `run` | 保留（只要还挂同一目录） | **全部丢失**，回到镜像原样 |
| 删掉 `~/redroid-arknights` | 丢失 | 丢失 |

也就是说：`/system` 的修改在容器的**可写层**里，不在 `/data` 里。

两种保命方式：

**A. 重建后重跑脚本（推荐）**

```bash
scripts/start-arknights.sh
scripts/fix-fingerprint.sh
# libndk 用 01 第 6 节的命令重铺
```

**B. 提交成新镜像**

```bash
sudo podman commit redroid-arknights redroid-arknights:configured
sudo podman images | grep redroid-arknights
```

以后用新镜像创建容器（`/data` 仍然单独挂）：

```bash
sudo podman run -itd --privileged --device /dev/dri:/dev/dri \
  -v ~/redroid-arknights:/data:rprivate,rbind \
  -p 127.0.0.1:5556:5555 --name redroid-arknights \
  redroid-arknights:configured \
  androidboot.use_memfd=1 androidboot.redroid_width=1280 \
  androidboot.redroid_height=720 androidboot.redroid_dpi=240 \
  androidboot.redroid_gpu_mode=host
```

> `commit` 会把可写层（包括 `/system` 的修改和容器内的日志/缓存）一起打包，镜像会变大。适合「配置好一套就不动了」的场景。

## 9. 重建后的检查清单

`podman rm` 之后按顺序过一遍：

```bash
# 1) 新容器起来了吗
sudo podman ps --filter name=redroid-arknights
adb connect 127.0.0.1:5556
adb -s 127.0.0.1:5556 shell getprop sys.boot_completed   # 1

# 2) 翻译层还在吗（rm 后一定不在）
adb -s 127.0.0.1:5556 shell 'su 0 md5sum /system/lib64/libndk_translation.so'
# 不是 0f8376... 就重铺第 6 节

# 3) guest libvulkan 禁用状态
adb -s 127.0.0.1:5556 shell 'su 0 ls /system/lib64/arm64/libvulkan.so*'
# 只应看到 .disabled；有 .so 就重做 6.4

# 4) 指纹
adb -s 127.0.0.1:5556 shell getprop ro.build.fingerprint | awk '{print length($0)}'
# 90；不是就跑 scripts/fix-fingerprint.sh

# 5) 系统设置
adb -s 127.0.0.1:5556 shell settings put global private_dns_mode off
adb -s 127.0.0.1:5556 shell settings put global captive_portal_mode 0

# 6) MTU
sudo /usr/local/sbin/redroid-fix-mtu redroid-arknights

# 7) 分辨率
adb -s 127.0.0.1:5556 shell wm size 1920x1080
adb -s 127.0.0.1:5556 shell wm density 320

# 8) 游戏还在吗（/data 在就还在）
adb -s 127.0.0.1:5556 shell pm list packages | grep hypergryph
```

> APK 装在 `/data`，所以重建容器**不用重装游戏**，登录态也在；只有 `/system` 的东西要重做。

## 附：为什么 guest 库也用了 Android 13 那一套

最初的直觉是「只换翻译层本身，guest 库保持镜像原版」，但实测发现：

- 只换翻译层 + Android 11 原版 guest 库 → 仍然 SIGABRT（`libvulkan.so` 那条）
- 禁用 guest `libvulkan.so` 后两种组合都能跑

最终采用的是「**整套 v0.2.3（翻译层 + arm64/arm 两套 guest 库）+ 禁用 libvulkan**」，这套配置连续稳定运行，也是与崩铁容器逐文件 md5 一致的配置（崩铁是唯一被证明能跑 Unity ARM 游戏的环境）。

`libvulkan.so.disabled` 的属主/权限会变成 `shell:shell 666`（因为是 `mv`），不影响使用，但可以顺手修：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 chown 0:0 /system/lib64/arm64/libvulkan.so.disabled'
adb -s 127.0.0.1:5556 shell 'su 0 chmod 644 /system/lib64/arm64/libvulkan.so.disabled'
```
