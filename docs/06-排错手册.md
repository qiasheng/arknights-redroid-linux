# 06 · 排错手册

按「先看哪一层」组织：容器 → ADB → 系统设置 → 游戏 → MAA。

先跑一遍 5 分钟体检，能定位 80% 的问题。

---

## 0. 五分钟体检

```bash
set -x
# 1) 容器在跑吗
sudo podman ps --filter name=redroid-arknights

# 2) ADB 通吗
adb connect 127.0.0.1:5556
adb devices

# 3) 开机完成了吗
adb -s 127.0.0.1:5556 shell getprop sys.boot_completed

# 4) 指纹长度（必须 ≤ 91，正常 90）
adb -s 127.0.0.1:5556 shell getprop ro.build.fingerprint | awk '{print length($0)}'

# 5) 翻译层 md5
adb -s 127.0.0.1:5556 shell 'su 0 md5sum /system/lib64/libndk_translation.so'

# 6) guest libvulkan 是否已禁用
adb -s 127.0.0.1:5556 shell 'su 0 ls /system/lib64/arm64/libvulkan.so*'

# 7) MTU
ip -o link show podman0 | sed 's/.*mtu \([0-9]*\).*/podman0 mtu=\1/'
CPID=$(sudo podman inspect -f '{{.State.Pid}}' redroid-arknights)
sudo nsenter -t "$CPID" -n ip -o link show eth0

# 8) 网络
adb -s 127.0.0.1:5556 shell ping -c 2 223.5.5.5

# 9) 屏幕状态
adb -s 127.0.0.1:5556 shell dumpsys power | grep mWakefulness

# 10) 游戏进程
adb -s 127.0.0.1:5556 shell pidof com.hypergryph.arknights
```

## 1. 容器层

### 容器起不来 / 一直 `Created` / `Exited`

```bash
sudo podman ps -a | grep redroid
sudo podman logs --tail 100 redroid-arknights
sudo podman inspect redroid-arknights --format '{{.State.Status}} {{.State.ExitCode}} {{.State.Error}}'
```

常见原因：

| 日志/现象 | 原因 | 处理 |
|---|---|---|
| `binder: open /dev/binder failed` | 内核没有 binder / binderfs 没挂 | 见下一条 |
| `Failed to mount /dev/binderfs` | 内核不支持 binderfs | 换内核（`linux` / `linux-zen` 一般都有） |
| `ashmem` 相关报错 | 新内核没有 ashmem | 确认启动参数有 `androidboot.use_memfd=1` |
| `permission denied` 访问 `/dev/dri` | 当前用户不在 `video`/`render` 组 | 用 rootful podman（`sudo`），或加组 |
| 端口被占用 | 5556 已被别的进程监听 | `ss -ltnp | grep 5556` |

检查 binder：

```bash
ls -l /dev/binder* /dev/binderfs 2>&1
zgrep -E 'CONFIG_ANDROID_BINDER' /proc/config.gz
```

本机是内核 7.2 的 Rust binder：

```
CONFIG_ANDROID_BINDER_IPC is not set
CONFIG_ANDROID_BINDER_IPC_RUST=y
CONFIG_ANDROID_BINDER_DEVICES=""
```

`BINDER_DEVICES` 为空时需要 binderfs，redroid 镜像会自己挂载；只要宿主 `/dev/binderfs` 存在、容器 `--privileged`，就能用。

### 容器重启后所有修改没了

- `podman restart`：保留可写层；
- `podman rm` + 新建：**丢失** `/system` 下的所有修改。

重建后必须重跑：

1. 01 第 6 节（libndk + 禁用 libvulkan）
2. 02（fingerprint）
3. 03 第 5 节（private DNS / captive portal）
4. 03 第 4 节（MTU）

或者用 `podman commit` 保存成镜像（见 01 第 8 节）。

### 磁盘越用越大

`/data` 在宿主的 `~/redroid-arknights`。游戏资源、日志、缓存都在这。

```bash
du -sh ~/redroid-arknights
sudo podman system df
```

清理：

```bash
# 容器内清 logcat / 临时文件
adb -s 127.0.0.1:5556 shell 'su 0 rm -rf /data/local/tmp/*'
adb -s 127.0.0.1:5556 shell 'su 0 logcat -c'

# 宿主机清无用镜像/容器（谨慎，别删正在用的）
sudo podman image prune
```

游戏内「清理缓存」会删掉已下载资源，下次要重下，慎用。

## 2. ADB 层

### `adb devices` 里没有 5556

```bash
adb connect 127.0.0.1:5556
adb devices -l
ss -ltnp | grep 5556
```

| 现象 | 原因 | 处理 |
|---|---|---|
| `Connection refused` | 容器没起 / 端口没映射 | 看容器状态和 `podman port` |
| `offline` | adbd 还没起来 | 等 10–30 秒，重新 `adb connect` |
| `unauthorized` | 容器里弹了授权框 | redroid 一般自动授权；不行就 `adb kill-server` 重连 |
| 列表里有两台 | 崩铁 5555 也在 | 命令里始终带 `-s 127.0.0.1:5556` |
| `no permissions` | udev / 权限问题 | 这是网络 ADB，不该出现；检查是不是连了 USB 设备 |

### `adb root` 之后设备消失

redroid 上 `adb root` 会重启 adbd，某些镜像版本直接起不来。**不要用 `adb root`**。

需要 root 时用容器内的 `su`：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 id'
# uid=0(root) gid=0(root) ...
```

如果已经 `adb root` 弄没了：

```bash
sudo podman restart redroid-arknights
adb connect 127.0.0.1:5556
```

### `adb install` 失败

| 报错 | 原因 | 处理 |
|---|---|---|
| `INSTALL_FAILED_NO_MATCHING_ABIS` | 没指定 ABI / APK 不含该 ABI | `adb install --abi arm64-v8a xxx.apk` |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | 装的版本比现有低 | 加 `-d`，或先卸载 |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | `/data` 满 | 清理或扩容数据目录 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名不一致（不同渠道包） | 先 `adb uninstall com.hypergryph.arknights` |
| `Failure [INSTALL_FAILED_TEST_ONLY]` | APK 带 testOnly | 加 `-t` |

装完确认走的是 ARM：

```bash
adb -s 127.0.0.1:5556 shell dumpsys package com.hypergryph.arknights | grep -A2 primaryCpuAbi
# primaryCpuAbi=arm64-v8a
```

## 3. 系统设置层

### 重启后网络又不行了

`settings` 和 MTU 都不完全持久。每次 `podman restart` 后补：

```bash
adb -s 127.0.0.1:5556 shell settings put global private_dns_mode off
adb -s 127.0.0.1:5556 shell settings put global captive_portal_mode 0
sudo /usr/local/sbin/redroid-fix-mtu redroid-arknights
```

### 屏幕黑 / 截图全黑

```bash
adb -s 127.0.0.1:5556 shell dumpsys power | grep mWakefulness
adb -s 127.0.0.1:5556 shell input keyevent KEYCODE_WAKEUP
adb -s 127.0.0.1:5556 shell wm dismiss-keyguard
adb -s 127.0.0.1:5556 shell svc power stayon true
adb -s 127.0.0.1:5556 shell settings put system screen_off_timeout 2147483647
```

### 分辨率不对

```bash
adb -s 127.0.0.1:5556 shell wm size
adb -s 127.0.0.1:5556 shell wm density
# 期望 Override size: 1920x1080 / Override density: 320
```

恢复默认：

```bash
adb -s 127.0.0.1:5556 shell wm size reset
adb -s 127.0.0.1:5556 shell wm density reset
```

> 改完分辨率后，MAA 的截图/坐标会按新分辨率适配；但 `input tap` 的坐标要自己换算。

### 时间不对

```bash
adb -s 127.0.0.1:5556 shell date
date
```

差太多会导致 TLS 失败、签到异常。重启容器通常会重新同步；不行就手动设：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 date $(date +%m%d%H%M%Y.%S)'
```

## 4. 游戏层

### 启动即闪退，logcat 有 `Fatal signal 6 (SIGABRT)`

先看这两行：

```bash
adb -s 127.0.0.1:5556 logcat -d | grep -E 'ndk_translation|libvulkan|SIGABRT' | tail -30
```

如果出现：

```
F ndk_translation: Unable to load library "libvulkan.so"
                   (upon using symbol "android_convertGralloc0To1Usage")
F libc: Fatal signal 6 (SIGABRT)
```

说明 guest `libvulkan.so` 没禁用。处理见 01 第 6.4 节：

```bash
adb -s 127.0.0.1:5556 shell 'su 0 mv /system/lib64/arm64/libvulkan.so /system/lib64/arm64/libvulkan.so.disabled'
sudo podman restart redroid-arknights
```

### 进主界面后几十秒进程消失

**指纹问题**，见 02。快速确认：

```bash
adb -s 127.0.0.1:5556 shell getprop ro.build.fingerprint | awk '{print length($0)}'
# >=92 或 0 → 坏
```

修复：

```bash
scripts/fix-fingerprint.sh 127.0.0.1:5556
```

### 卡在加载页，永远不进登录

不是 bug。点金色菱形：

```bash
# 1920x1080
adb -s 127.0.0.1:5556 shell input tap 960 984
# 1280x720
adb -s 127.0.0.1:5556 shell input tap 650 660
```

先截图确认当前确实是加载页：

```bash
adb -s 127.0.0.1:5556 exec-out screencap -p > /tmp/ark.png
```

### 停在「正在释放神经递质」/ 资源下载 0%

网络 / MTU，见 03：

```bash
sudo /usr/local/sbin/redroid-fix-mtu redroid-arknights
CPID=$(sudo podman inspect -f '{{.State.Pid}}' redroid-arknights)
sudo nsenter -t "$CPID" -n ping -M do -s 1464 -c 3 8.8.8.8
```

### 提示版本过低 / 强制更新

游戏内热更没完成，或者 APK 太旧。重新下载最新 APK，`-r` 覆盖安装（保留数据）：

```bash
adb -s 127.0.0.1:5556 install -r --abi arm64-v8a arknights-latest.apk
```

跨大版本时可能必须卸载重装，但那样会丢登录态（`/data` 里的账号数据），需要重新登录。

### 登录页一直转圈 / 提示网络异常

```bash
adb -s 127.0.0.1:5556 shell ping -c 2 223.5.5.5
adb -s 127.0.0.1:5556 shell ping -c 2 www.hypergryph.com
```

- ping 通但游戏连不上：看 MTU（大包被丢）。
- ping 不通：容器网络 / 宿主网络。
- 都通但登录失败：可能是账号风控 / 需要手动验证，换手机热点试一次。

### 游戏没声音

redroid 默认没有音频输出，这是预期行为。MAA 不需要声音。要声音得配 PulseAudio + 额外的 redroid 音频参数，和本方案无关。

## 5. MAA 层

### MAA 起不来 / `MaaCore.dll 加载失败`

```bash
WINEPREFIX=~/Games/maa-prefix winetricks -q vcrun2022
```

并确认：

- MAA 是完整包解压，`MaaCore.dll`、`MAA.dll`、`resource/` 都在；
- Lutris 里 `disable_runtime: true`；
- Wine 版本不是太老（>= 9，实测 11.0）。

### MAA 连不上 5556

```bash
# 先在宿主确认
adb connect 127.0.0.1:5556
adb devices

# 再确认 MAA 的 AdbPath
grep -o '"AdbPath"[^,]*' ~/Games/MAA/config/gui.new.json
grep -o '"Address"[^,]*'  ~/Games/MAA/config/gui.new.json
```

`AdbPath` 必须是 `Z:\...\adb.exe`，`Address` 必须是 `127.0.0.1:5556`。

### 标题显示 5555 而不是 5556

MAA 自动选了第一台设备。在连接设置里把地址写死为 `127.0.0.1:5556`，或者先 `adb disconnect 127.0.0.1:5555`（会断崩铁，不建议）。

### 截图成功但点击无效

依次试触控模式：

1. `MiniTouch`（默认，实测可用）
2. `MaaTouch`
3. `ADB`（最慢，但兼容性最好）

还不行就看游戏是不是在动画/过场里，或者屏幕是不是休眠。

### MAA 日志在哪

```
~/Games/MAA/debug/gui.log
~/Games/MAA/debug/asst.log
```

`asst.log` 里搜 `Connect`、`Click`、`Recognize`、`ret: false`。

### MAA 更新失败

`MAA.Updater.exe` 在 Wine 下经常失败。手动更新：

1. 下载新的完整包；
2. 解压到新目录；
3. 把旧目录的 `config/`、`data/`、`debug/` 复制过去；
4. 修改 Lutris 条目的 `exe` / `working_dir`（如果目录变了）。

### 419 个文件缺失

解压不完整。点「暂不处理，继续启动」可以继续用，但建议重新解压完整包。缺的主要是壁纸和旧作业文件，不影响核心任务。

## 6. 宿主层

### `pkill -f` 把自己杀了

```bash
# ❌ 危险：pattern 会匹配到 pkill 自己的命令行
pkill -f lutris
```

现象：SSH 断开、终端退出、命令没执行完。因为 `pkill -f` 会匹配整条命令行，而命令行里就包含 `lutris`。

正确做法：

```bash
# 用进程名精确匹配
pkill -x lutris
# 或者先看再杀
pgrep -a lutris
kill <pid>
```

### 装 `tcpdump` 把系统搞坏

Arch 上 `pacman -S tcpdump` 可能触发 `libcrypto.so=3-64` 依赖冲突，升级/降级 OpenSSL，进而影响 podman、git、curl。**不要为了抓包随便装它。**

替代：用 `nft`/`ss`/`ip` 看统计，或者在容器里用 toybox 的 `tcpdump`（如果有）。

### 端口被占

```bash
ss -ltnp | grep -E '5555|5556|5037'
```

- `5037`：adb server；
- `5555`：崩铁；
- `5556`：方舟。

不要随便 kill 5037 之外的进程；`adb kill-server` 只会影响 adb。

### 系统更新后 redroid 挂了

内核升级后 binder 配置可能变。检查：

```bash
uname -r
ls -l /dev/binder*
zgrep -E 'CONFIG_ANDROID_BINDER' /proc/config.gz
```

必要时重启回旧内核，或换回 `linux` / `linux-lts`。

## 7. 一页速查

| 症状 | 最可能原因 | 一条命令验证 |
|---|---|---|
| 启动即 SIGABRT | guest libvulkan 没禁用 | `adb shell 'su 0 ls /system/lib64/arm64/libvulkan.so*'` |
| 进游戏几十秒被杀 | fingerprint >= 92 | `adb shell getprop ro.build.fingerprint \| awk '{print length($0)}'` |
| 卡加载页 | 没点金色菱形 | 截图看底部 |
| 下载 0% / 断流 | MTU 1500 | `nsenter ... ping -M do -s 1464` |
| 黑屏 | 屏幕休眠 | `dumpsys power \| grep mWakefulness` |
| 点不动 | 触控模式 | 换 MiniTouch |
| MAA 连不上 | AdbPath / 端口 | `grep AdbPath gui.new.json` |
| 设备选错 | 5555/5556 混淆 | 地址写死 5556 |
| 容器修改丢失 | `podman rm` 过 | `grep fingerprint /system/build.prop` |
| 系统网络正常、容器不正常 | DNS/门户检测 | `settings get global private_dns_mode` |
