# 04 · 启动流程与坐标：金色菱形是什么

## 1. 冷启动的完整状态机

```
容器启动
  └─ Android 开机（约 20–40 秒，sys.boot_completed=1）
       └─ am start 游戏
            └─ 黑屏 / 厂商 Logo（2–5 秒）
                 └─ 热更校验（版本检查、资源完整性）
                      ├─ 需要更新 → 下载资源（见 03 的 MTU）
                      └─ 校验通过
                           └─ 加载页（Loading / 「正在释放神经递质」）
                                └─ ★ 底部金色菱形（必须点！）
                                     └─ 登录页
                                          └─ 「开始唤醒」
                                               └─ 主界面（基建/终端）
```

每一步都可能被误判成「卡死」。下面逐段说怎么确认、怎么过。

## 2. 起游戏

Activity 名是固定的：

```bash
adb -s 127.0.0.1:5556 shell am start -W \
  -n com.hypergryph.arknights/com.u8.sdk.U8UnityContext
```

`-W` 会等 Activity 启动完成并打印 `Status: ok` / `LaunchState`。如果游戏已经在运行，这条命令只是把它切到前台。

确认前台是谁：

```bash
adb -s 127.0.0.1:5556 shell dumpsys window | grep -E 'mCurrentFocus|mFocusedApp'
```

正常应该是：

```
mCurrentFocus=Window{... u0 com.hypergryph.arknights/com.u8.sdk.U8UnityContext}
mFocusedApp=ActivityRecord{... com.hypergryph.arknights/.u8.sdk.U8UnityContext ...}
```

如果前台是桌面（`com.android.launcher3`），说明游戏没起来或者已经退出：

```bash
adb -s 127.0.0.1:5556 shell pidof com.hypergryph.arknights
adb -s 127.0.0.1:5556 logcat -d | grep -iE 'arknights|FATAL|Force finishing' | tail -50
```

## 3. 加载页：必须点金色菱形

这是最反直觉的一步。

**这个页面不会自动前进。** 它底部有一个很暗的金色菱形（或者说「开始」按钮），必须点它才进登录页。静置 3 分钟、10 分钟都一样。很多人在这里以为游戏卡死 / 翻译层挂了 / 资源没下完。

### 3.1 坐标

游戏分辨率 **1920×1080**（`wm size` override 之后）：

| 目标 | 坐标 |
|---|---|
| 金色菱形（加载页） | **(960, 984)** |
| 「开始唤醒」（登录页） | **(960, 765)** |

```bash
adb -s 127.0.0.1:5556 shell input tap 960 984
```

如果是 **1280×720**：

| 目标 | 坐标 |
|---|---|
| 金色菱形 | **(650, 660)**（MAA 模板中心；实测约 640, 656） |
| 「开始唤醒」 | **(640, 510)** |

换算公式（从 1280×720 模板到实际分辨率）：

```
x_actual = x_1280 * width  / 1280
y_actual = y_720  * height / 720
```

MAA 内部模板就是 1280×720，所以 1080p 下所有模板坐标乘 1.5。

### 3.2 怎么自己找坐标

不要盲猜。截图，然后看图：

```bash
adb -s 127.0.0.1:5556 exec-out screencap -p > /tmp/ark.png
```

- 有桌面环境：直接打开 `/tmp/ark.png`，量像素。
- 无桌面：用 ImageMagick 裁切放大底部：

  ```bash
  magick /tmp/ark.png -crop 1920x200+0+880 +repage -resize 50% /tmp/bottom.png
  ```

- 也可以 `scrcpy -s 127.0.0.1:5556 --no-audio` 直接看实时画面，鼠标点一下，终端会打印触摸坐标（scrcpy 默认不打印，但画面足够用来定位）。

### 3.3 为什么 MAA 能自动过这一页

MAA 的 `StartUp` 任务里有 `GameStart` 模板：

```json
"GameStart": {
  "action": "ClickSelf",
  "roi": [550, 600, 200, 120],
  "templThreshold": 0.7,
  "postDelay": 3000
}
```

`roi` 是 1280×720 下的区域，中心 `(650, 660)` → 1080p 下 `(975, 990)`，正好覆盖那个菱形。所以只要 MAA 的 StartUp 任务开着，它会自己点，不需要你手点。

「开始唤醒」对应：

```json
"StartToWakeUp": {
  "action": "ClickSelf",
  "roi": [520, 460, 240, 100]
}
```

中心 `(640, 510)` → 1080p `(960, 765)`。

## 4. 登录页与首次登录

- 登录页的按钮是「开始唤醒」。点它之后会读账号登录态，直接进主界面。
- **首次登录必须手动**：国服要手机号 + 短信验证码，MAA 做不了，也没有合法的自动化方式。
- 登录态保存在容器 `/data` 里（bind mount 到 `~/redroid-arknights`），所以：
  - `podman restart`：登录态保留；
  - `podman rm` + 重建：只要还挂同一个 `~/redroid-arknights`，登录态也保留；
  - 删掉数据目录：要重新登录。

如果登录页出现「账号已过期 / 需要重新登录」，只能手动过一次。

## 5. 更新弹窗

大版本更新后，登录前可能弹「维持原有配置 / 使用推荐配置」之类的对话框。这个框的坐标**随版本变化**，不要写死。

在 1920×1080、我们遇到的那一版里：

| 目标 | 坐标 |
|---|---|
| 「维持原有配置」勾选框 | (621, 542) |
| 「确认」按钮 | (965, 664) |

> 仅供同版本参考。换版本后先截图确认，或者干脆交给 MAA：MAA 的 StartUp 流程能处理大部分公告/弹窗。

## 6. 让屏幕别睡

MAA 无人值守时，屏幕一黑，截图就是黑的，点击也可能不生效。

```bash
# 插着电时保持常亮
adb -s 127.0.0.1:5556 shell svc power stayon true

# 屏超时拉到最大（约 24 天）
adb -s 127.0.0.1:5556 shell settings put system screen_off_timeout 2147483647

# 关掉锁屏
adb -s 127.0.0.1:5556 shell locksettings set-disabled true
```

检查：

```bash
adb -s 127.0.0.1:5556 shell dumpsys power | grep -E 'mWakefulness|Display Power'
# mWakefulness=Awake
```

如果已经是 `Asleep`，先唤醒：

```bash
adb -s 127.0.0.1:5556 shell input keyevent KEYCODE_WAKEUP
adb -s 127.0.0.1:5556 shell wm dismiss-keyguard
```

> redroid 是无头的，「屏幕」是虚拟显示。`stayon true` 在 redroid 上一般有效（它把容器当成充电中），但 `screen_off_timeout` 才是最稳的。

## 7. 启动耗时参考

| 阶段 | 大约耗时 |
|---|---|
| 容器从 `podman start` 到 `sys.boot_completed=1` | 20–40 秒 |
| `am start` 到出现加载页 | 3–10 秒 |
| 热更校验（无更新） | 5–20 秒 |
| 加载页 → 点菱形 → 登录页 | 2–10 秒 |
| 点「开始唤醒」→ 主界面 | 3–15 秒 |

MAA 的 StartUp 任务默认会等，不要因为它「看起来没动」就手动干预。第一次配置时可以在旁边看 logcat：

```bash
adb -s 127.0.0.1:5556 logcat | grep -iE 'Unity|arknights|ActivityTaskManager'
```

## 8. 常见「卡住」对照表

| 停在哪 | 怎么确认 | 处理 |
|---|---|---|
| 黑屏，无 Logo | `pidof` 有没有进程；logcat 有没有 `SIGABRT` | 看 01 的 `libvulkan.so` 是否禁用、翻译层 md5 |
| Logo 后黑屏很久 | logcat 有没有热更/下载日志 | 网络 MTU（03）；等 1–2 分钟 |
| 加载页不动 | 截图看底部有没有金色菱形 | 点 (960,984) / (650,660) |
| 点菱形没反应 | 是不是点在了菱形上方；分辨率是不是 1080p | 重新截图定位；确认 `wm size` |
| 登录页没有「开始唤醒」 | 是不是弹了公告/更新框 | 截图看，先关弹窗 |
| 点开始唤醒后回到桌面 | `pidof` 消失，logcat 无 FATAL | **指纹问题**（02） |
| 主界面几秒后消失 | 同上 | **指纹问题**（02） |
| 一直转圈连不上 | 容器 `ping` 通不通 | MTU / DNS（03） |

## 9. 手动操作 vs MAA

- **手动**：`input tap` 是「盲点」，点错位置可能进错界面（比如点进主线关卡、花掉理智）。操作前一定先截图确认当前界面。
- **MAA**：它每一步都先截图识别，识别不到会重试/报错，不会盲点。所以日常交给 MAA，手动只用于首次登录和排错。
- 不要同时用 scrcpy 和 MAA 操作：两边都在发触摸事件，会互相打断。
